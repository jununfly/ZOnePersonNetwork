### 多仓库横向采集的方法论（复用价值高）

- **统一 brief 的 fallback 策略**：criterion keyword 全部用纯内容短语（非路径子串）时，每个仓库 hints 为空 → compiler fallback 只读该仓库根 `README.md`（+ manifest），天然适合横向对齐。若要让某个仓库的 `docs/**/*.md` 进入 sealed 范围，用**只在该仓库 tree 里出现的路径子串**（本轮 `agent-self-service-collaboration` 只对 ZAgenticOPN 生效）；`locate` 是 per-repository 的，不会禁用其他仓库的 fallback。
- **关键词设计**：每个 criterion 给 3–6 个**来自不同项目 README 的具体长短语**，`keywords.some` 让每个仓库各命中一条，直接形成矩阵；避免 `board` / `memory` / `SQLite` 这类宽泛词（会在 README 顶部误命中）。命中率 49/130，其余 81 个 unknown 显式保留。
- **采集前必做路径碰撞预检**：脚本把全部 keyword × 全部仓库 blob 路径做小写包含比对。本轮查出 3 处：`CONTEXT.md` 误命中 `*_context.md` / `templates/CONTEXT.md`（非 canonical、已移除）、参照物路径子串（有意保留）。这一步避免重演 herdr v1 的语义错配。
- **配额与超时**：10 仓库匿名 60/h 不够，用 `GITHUB_TOKEN=$(/opt/homebrew/bin/gh auth token)` + `ZJ_RESEARCH_CLI_TIMEOUT_SECONDS=900` + brief `deadlineMs=600000` / `maxFiles=120`。
- **problem-discovery 的 IR 契约**：`stage=problem-discovery` → `graduationCriteria=[]`、省略 `versionSkew`、退出条件写进 recommendations prose；`unknownCriteria` 非空 → `informationGaps.status` 必须是 `has-gaps`。编译器 `render-html` 的 concepts key ASCII slug 契约在本轮继续生效（10 个 slug 通过）。
