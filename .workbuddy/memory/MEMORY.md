- **zj-research 架构决策（终态，zj 2026-11-09 拍板「彻底独立」）**：`zj-research` 是**纯协议适配层**，**不捆绑任何编译器、零 ZHarness/dsh/DeepSeek 依赖**。调用方必须自带一个说 `zj-research-cli/v1` 的编译器，经环境变量 `ZJ_RESEARCH_CLI` 提供；评估编译器经 `ZJ_RESEARCH_EVAL_CLI`（说 `zj-research-eval-cli/v1`）提供。`command()` 在 env 未设时**显式抛 RuntimeError 并给 setup 指引**，绝不静默回退到 vendored artifact。理由：ZOnePersonNetwork 是 0 实现的绿地项目，zj-research 作为「跨 Agent 可运行的通配型技能」不该绑死任何具体编译器/上游。**历史纠正**：早先试过「切依赖但保留改名 artifact」（`dsh-research-compiler-artifact-0.1.0.tgz` + `compiler-lock.json` provenance.metadata），zj 推翻该方案 → 改为彻底独立：`artifacts/` 已清空（tgz 移出到 `/tmp/zj-research-artifact-backup/`，可恢复）、`compiler-lock.json` 已删、`research_cli.py`/`research_eval_cli.py` 删掉 `artifact_command`/`file_sha256`/`compiler_cache` 等打包解包逻辑、文档/测试中所有 ZHarness/dsh/DeepSeek 引用已清除。`collect/` 目录已空（`test_lock_provenance.py` 等旧守卫随方案废弃一并移除）。**守卫**：`tests/verify_independent_runtime.py`（artifacts/ 无 `*.tgz`、无 `compiler-lock.json`、`ZJ_RESEARCH_CLI` 未设时 `command()` 抛错、源码无 vendor token）——GREEN；`tests/verify_golden_contract.py`（对外部缓存 node 编译器 `~/.cache/zj-research/compiler/e5297042…/lib/bin.js`+`eval.js` 跑 runtime 契约 + 7 编译器用例 + 10 评估用例）——GREEN。本地/测试用外部指针即该缓存编译器；artifact 字节（lock SHA `e5297042…`）仍在 `/tmp` 备份中。
- **编译器版本钉（关于编译器本身的事实，与 zj-research 无关，现交由消费方负责）**：collect 对 brief 的 `repositories[].revision` 是**死输入**——`researchBriefFingerprint` 把 repositories 归一化为仅 `{owner,name}`（丢 revision），`resolveRevision` 永远 `getBranch(default_branch)` → 钉默认分支 HEAD（RED 实证：tag `v0.8.1`=`b1ea927…` ≠ ledger 实际 `05259b84…`）。因 zj-research 不再捆绑编译器，版本钉的责任转移给消费方：要么把编译器路径/sha 自身钉死，要么修编译器接入 revision。早先 collect 的 ledger 仍保留 `CTX::*-pin-deviation` 历史标注（仅注释，不影响 zj-research 适配层）。
- 横比 collect 的弱证据根因：`HeuristicResearchNavigator.locate` 用 criterion 的 **keyword 做路径子串匹配**选 canonical 文件。若 keyword 恰好是某非目标文件的路径子串（如 multica 的 `config-strategy` 含 `Lark` → 命中 `docs/lark-*.md` 把"媒体/配额维护"文档读进来），其余场景的 content keyword（review/replay/workspace/diff）又在该已读文档里命中 → 多条 Evidence 全误钉到错文件，产生 sealed 但语义错配的 Evidence（判 native 仅因有 sealed ID）。**修法**：用**路径唯一 keyword**（如 `readme.md`，不匹配 `README.ja/zh` 也不匹配 `Dockerfile`）把场景锚定到目标 canonical 文件；并去掉会命中 manifest 的 keyword（如 `Docker` → 误钉 `Dockerfile`）。修好后须逐条复核摘录确为对应场景原文，再撤掉 `CTX::*-weak-evidence`（改为 `CTX::*-evidence-anchored`）。
- collect 导航：keyword 既是**路径子串**（命中 canonical 路径才选文件；只要存在 hint，根 README fallback 不触发）又是**正文匹配词**（`excerptForCriterion` 取首个命中行 ±1/+5 行）。裸路径 keyword（如 `README.md`）会在别的文件正文被误命中 → 语义错配。**解法**：把路径导航 keyword 隔离到语义本就在该文件的 criterion，其余 criterion 只用目标文件独有的正文短语；hints 非空且每个文件都被选中时，可同时覆盖 README / AGENTS / Cargo.toml 多文件。canonical 路径只认 `docs/**/*.md`、`(readme|agent|claude|architecture)*.md` 与少数 manifest，`.mdx` / `SKILL.md` / `CONTRIBUTING.md` 结构上进不了 sealed ledger，须作非 sealed 一手阅读。采集后必须逐条语义复核，`unknownCriteria: []` 不代表证据充分。
- 技术调研走 `zj-tech-research-report` + `zj-research` 组合：先 collect 生成 commit-pinned sealed ledger，再写 technical-decision-brief 与 `technical-c4/v1` Report IR，最后用 `publish_report.py` 产出 Markdown/HTML/receipt。**不要手写竞争版报告**，编译器渲染字段集固定（riskRegister / graduationCriteria 不渲染，需在 recommendations prose 中复述）。
- `render-html` 硬契约：concepts 的 `key` 必须是纯 ASCII 小写 slug（`[a-z0-9][a-z0-9._-]*`），因为 `validateConceptReferences` 要求 `- Key: \`identifier\`` 与 `[[identifier]]` 一一对应；含空格/中文/括号的 key 会直接发布失败。编译器 HTML 自带 30 行 trailing whitespace 属内嵌 mermaid runtime 固有产物，不要 post-process。
- 能力结论只认 sealed Evidence ID；本地未推送 checkout 的观察必须标注为非 sealed，只用于风险与对齐项。
- 多仓库横向模块调研（`docs/reasearch/opn-landscape/`）：统一 brief 用**纯内容短语**让每仓库 fallback 读根 README；只给参照物用「只在其 tree 出现的路径子串」引 `docs/**/*.md`（`locate` 是 per-repository，不影响其他仓库 fallback）。每个 criterion 给多个来自不同项目的具体长短语形成矩阵，避免宽泛词。**采集前必须用脚本做全 keyword × 全 tree 路径碰撞预检**。10 仓库需 `GITHUB_TOKEN=$(/opt/homebrew/bin/gh auth token)` + `ZJ_RESEARCH_CLI_TIMEOUT_SECONDS` + 大 `deadlineMs/maxFiles`。`problem-discovery` 用 `graduationCriteria=[]`、省略 `versionSkew`、unknown 非空则 `informationGaps=has-gaps`。
