# 采用形态：项目级作废，功能级恢复

2026-11-13 的产品设计裁决：推翻 charter（2026-11-08）第 6 节「采用形态结论层作废」的**项目级**判定，改为**功能级恢复**。

**背景**：charter 当时把 zagenticopn / orca / herdr 三份调研报告的「采用 / 拒绝 / 阶段退出」结论整体作废，仅留事实层作素材，目标转向横向模块矩阵。但在 R1 产品设计时 zj 明确：调研对象大部分功能已成形可用，应直接摄取（避免 0→1 工作量）；不成熟 / 设计中的进「待 PoC 清单」。

**决策**：调研产物按**成熟度分池**而非按项目定夺——已成形且实际可用的功能进 A 池（默认 ① 复制代码，Human 确认可降级 ② 只取契约另写），不成熟 / 设计中的进 B 池（待 PoC 清单）。判定用三条硬闸门（可运行实现 / 测试契约门 / 法律有权 fork+own），闸门是准入不是排序。

**为何立 ADR**：难逆——改变了全部调研如何喂养产品的方式；无上下文会令人费解——外人看 charter 会以为「不采用任何调研对象」，实际是「按功能挑着用」；真实取舍——在「全盘照搬某项目模块」与「纯从 0 自研」之间选了第三条路：按功能成熟度选择性摄取。

**Consequences**：charter 第 6 节的作废声明在**项目级**仍有效（不把任何整份报告当采用决策），但**功能级**恢复采用判定；R3 的 A/B 两池初分提案（`docs/designs/product-module-map.md`）即此决策的首个产物。闸门细节见 `ZJ-CONTEXT.md` 的「两池判定闸门」。
