# 采用形态：项目级作废，功能级恢复

2026-11-13 的产品设计裁决：推翻 charter（2026-11-08）第 6 节「采用形态结论层作废」的**项目级**判定，改为**功能级恢复**。

**背景**：charter（2026-11-08）曾把 zagenticopn / orca / herdr 三份调研报告的「采用 / 拒绝 / 阶段退出」结论整体作废，仅留事实层作素材。此后研究范围扩展为 13–14 个仓库的横向调研——横向模块矩阵 SoT、14 仓库成熟度验证（non-sealed，仅作验证门）、12 场景 × 14 项目场景锚定横比（SCENE-SET::zopn-v1，zj 2026-11-20 ratify 已签发）——内容从模块覆盖深化到 charter §4 的六维（产品设计 / 技术设计 / 复用边界 / 组合顺序 / 人机分工 / 工作量信号）与 Human 门六方对比。zj 在 R1 产品设计时明确：调研对象大部分功能已成形可用，应直接摄取（避免 0→1 工作量）；不成熟 / 设计中的进「待 PoC 清单」。三份旧报告的结论层作废只针对**采用形态**判定，不阻止功能级摄取；charter §7「不做总体产品方案 / 技术方案」的非目标已由 R1 产品设计阶段解除。

**决策**：调研产物按**成熟度分池**而非按项目定夺——已成形且实际可用的功能进 A 池（默认 ① 复制代码，Human 确认可降级 ② 只取契约另写），不成熟 / 设计中的进 B 池（待 PoC 清单）。判定用三条硬闸门（可运行实现 / 测试契约门 / 法律有权 fork+own），闸门是准入不是排序。

**为何立 ADR**：难逆——改变了全部调研如何喂养产品的方式；无上下文会令人费解——外人看 charter 会以为「不采用任何调研对象」，实际是「按功能挑着用」；真实取舍——在「全盘照搬某项目模块」与「纯从 0 自研」之间选了第三条路：按功能成熟度选择性摄取。

**Consequences**：charter 第 6 节的作废声明在**项目级**仍有效（不把任何整份报告当采用决策），但**功能级**恢复采用判定。三闸门细则见 `ZJ-CONTEXT.md` 的「两池判定闸门」。本决策的首个产物是产品模块地图与 A/B 两池决策（`docs/designs/product-module-map.md`，R3 · zj 2026-11-16 拍板，现为 `authority: primary` 权威页）；M3 Human 门的功能设计权威页（`docs/designs/human-gate-model.md`，`opn.human-gate-model`）是该摄取规则在 L1 语义层的首个具体落地。
