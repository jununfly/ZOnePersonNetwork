## 1. 关键设计约束（为什么全用长短语）

81 个 unknown 与 40/49 README-only 的根因之一，是裸路径 keyword 既当路径 hint 又当正文词时会误选文件；同时编译器的 canonical 白名单很窄（`docs/**/*.md`、若干命名 md、少量 manifest），`LICENSE` / `.github/workflows/*` / `tests/*` / `fixtures/*` 都不在白名单，裸路径词会命中非 canonical 路径。
→ 本草案所有 keyword 一律用**带空格/标点的判别性长短语**（正文匹配词），尽量避免成为路径子串；具体碰撞结论见 `2026-11-13-precheck.py` 与 `2026-11-13-collision-list.md`。
注意：长短语不会充当路径 hint，因此若要读取白名单外的 `LICENSE`/workflow/fixture 原文，属 charter §8 的「非 sealed 一手阅读」，不在本轮 sealed collect 口径内，另行处理。同理，本草案 41 个 keyword 均非路径子串（见 collision-list：canonical hint 命中数也为 0），即**不提供任何文件选择 hint**；正式采集若要钉住 manifest / `docs/**/*.md`，需补入白名单内的 canonical 路径 hint（如 `package.json`），它们按规则计入「可接受」而非碰撞。

## 2. Criteria（6 条）

### C1 `mat-installable-runnable` — 可安装 / 可运行实现
- **目的**：把「README 说有某功能」与「真有能装能跑的制品」分开。这是分池的第一道硬门槛：没有可复现的安装/构建/启动路径，只能进待 PoC。
- **建议的判别性长短语**：
  - `install it globally with npm install -g`
  - `to build from source, run`
  - `requires Node.js 20 or Python 3.11 or newer`
  - `prebuilt binaries are published for macOS and Linux`
  - `start the server with docker compose up`
  - `a single compiled binary with no runtime dependencies`
  - `published to the npm registry / PyPI`

### C2 `mat-behavior-contract-testgate` — 可复核的行为契约 / 测试门
- **目的**：成熟度不是「有代码」，而是「行为被钉住且可复核」。找 CI、测试命令、断言、合并门、契约测试，判断是「实际可用」还是 demo。
- **建议的判别性长短语**：
  - `run the full test suite with`
  - `all tests must pass before a pull request can be merged`
  - `continuous integration runs on every push`
  - `contract tests assert the request and response shape`
  - `coverage must not fall below`
  - `the state machine transitions are verified by`
  - `snapshot / golden-file comparison is committed`

### C3 `mat-release-version-skew` — 发版与版本偏斜
- **目的**：判断是否有稳定发版节奏与版本契约；client/server、schema 迁移的版本偏斜处理是「已成形可用」的关键，缺失则进待 PoC。对应 charter §4「升级与版本偏斜」维度。
- **建议的判别性长短语**：
  - `released under semantic versioning`
  - `see the changelog for breaking changes`
  - `this version requires a migration from`
  - `the server and client must be on the same minor version`
  - `pinned to a specific commit in the manifest`
  - `a deprecation policy for the public API`
  - `tagged releases are published on a fixed cadence`

### C4 `mat-license-forkability` — 上游治理与 license（能否改造 / 是否只能 fork）
- **目的**：直接服务分池 —— 能不能合法改造、上游是否接纳贡献、是否只能 fork 自维护，是「摄取」的硬门槛。herdr 那轮已见「只收文档不收代码 PR」型治理风险，需显式取证。
- **建议的判别性长短语**：
  - `licensed under the Apache License, Version 2.0`
  - `released under the MIT License`
  - `we do not accept code contributions, only documentation`
  - `all contributors must sign a Contributor License Agreement`
  - `pull requests are reviewed and merged by the maintainers`
  - `fork the repository to customize it for your own deployment`
  - `the project is archived and no longer maintained`

### C5 `mat-contract-fixtures` — 契约 fixture 是否存在
- **目的**：charter §7 与 module-matrix §7 都把「先写黑盒/契约 fixture 再决定是否抽取」作为准入方式；没有 fixture 的实现无法判定「可摄取」，只能进待 PoC。
- **建议的判别性长短语**：
  - `golden files are stored alongside the tests`
  - `black-box contract fixtures define the expected behavior`
  - `the testdata directory contains reproducible inputs and outputs`
  - `snapshot tests are committed to the repository`
  - `a minimal reproducible example is provided`
  - `the fixture pins the wire format`

### C6 `mat-impl-beyond-readme` — 实现层证据（把 README-only 声明升级）
- **目的**：直接针对 40/49 来自根 README 的缺口；要求命中设计规格 / ADR / 状态机 / 协议 / 持久化等实现层文档，把 unknown 格升级成可判定成熟度，而不是再收一条模块清单。
- **建议的判别性长短语**：
  - `as specified in the design document`
  - `the architecture decision record describes`
  - `the state machine transitions are defined as`
  - `the wire protocol is specified in`
  - `the schema is enforced at runtime`
  - `the persistence substrate is`
  - `see the dedicated specification page for`
