### 2.1 产品模块构成（对痛点 1）

- **F1 — 没有单一项目覆盖全部 13 个维度**：最高 `qm 9/13` 与 `ZAgenticOPN 9/13`，最低 `dmux 1/13`；81 个组合为 unknown。模块构成在不同项目里被切成不同集合，照搬任一项目都会漏格。Evidence：覆盖矩阵由 49 条 Evidence 汇总，代表 `114f13c4…`（qm 身份/scope）、`90b8b4fc…`（tasktrooper 任务板）、`9101cfa7…`（opencode-coord 工作项+账本）、`3f9dde43…`（ZAgenticOPN capability-map）。
- **F2 — qm 的模块单位是「scope」，不是 Work Item**：`Every person / room has its own scoped memory, files, keychain view, permissions, crons, web apps, and durable sandbox`，并声明 `Personal and shared scopes`、`Shared skills`、`Background work (Crons, watches, inbound webhooks)`。Evidence: `114f13c4c8afc8424cdc1971`、`1fcc9288e24457d7fa94240e`、`ad01939f1a7e220edf96928f`、`b30ee3590bb6aaead44befb3`。
- **F3 — ZAgenticOPN 的模块单位是「语义所有权」**：`语义所有权` 表固定 `AgentInstance/device_id`、`CollaborationScope`、Work Item eligibility / lifecycle / Claim authority、`Result/review semantics`、`Human action script`、`Health scorecard`；PRD 用 R1–R12 把稳定身份、private context、shared coordination context、原子 claim、provenance 等拆成可验收需求。Evidence: `5da1a8117f4c7765b67113c4`、`3f9dde435394108a69009858`、`37c46d46405b7d6055e568d5`、`ddea4d90bb2b7e250b08b616`、`6814fc75fc59e1f02bb5f756`。
- **F4 — 执行编排层几乎都以 git worktree 为隔离单元**：agetor `each task in its own git worktree`、lanes `issues, worktrees, sessions, one board`、mozzie `isolated git worktrees`、dmux `Manage multiple AI coding agents in isolated git worktrees`。Evidence: `e6275d13fae90b3ea49ca276`、`a8434e60ad92db78fedb7af2`、`6676d3f26c9b4f77443c5d2a`、`205fcc6c54e6dcc370eeeb85`。
- **F5 — 任务板/生命周期有多套互不相容的状态机**：opencode-coord `Roles, work items, messages, progress and history ... one append-only ledger` 与 `Items with a life cycle`（九态）、lanes `Each card is a task`、mozzie `Work item lifecycle`、tasktrooper `A board of tasks`、ZAgenticOPN `available → claimed → awaiting_agent_review → completed`。Evidence: `9101cfa7145332b317a9353e`、`fc77e9f1b10477d753e74fab`、`14bb8d6ea36e18107fd51b3c`、`90b8b4fc0e74bc12214889c4`、`3f9dde435394108a69009858`。
- **F6 — 共享知识层有两种相反实现**：mem-vault `pure Markdown on a cloud-synced directory` + `session-blackboard convention (CONTEXT.md)`，无数据库无服务；qm 是 `Postgres persistence layer` + `scoped memory`；tasktrooper 是 `Memories in four scopes`。Evidence: `de5482ebaca9a76160284089`、`151608571341f37ee2297dcb`、`e38a7af1b2e8472ed82f40dd`、`d2423363b8e0d64ec8ce61cc`。

### 2.2 技术设计（对「技术设计」调研目标）

- **F7 — qm 的架构是 central core + Postgres + 固定工具面 + 每 scope 沙箱**：`Every turn runs through a central core`、`A Postgres persistence layer holds user data, session history`、`small, fixed tool surface`、`execute` 在 scope 自己的隔离沙箱里跑；`Every substrate (session store, sandbox, memory) sits behind an interface`。Evidence: `e38a7af1b2e8472ed82f40dd`、`3ae4f38b4de2d1769a598bc0`。
- **F8 — 本地优先的技术栈差异**：tasktrooper `embedded Postgres + Go backend`、agetor `One local API` over HTTP/SSE 只监听 `127.0.0.1`、lanes `SQLite on your machine`、mem-vault 纯 Markdown 无数据库。Evidence: `834655c524dca5a255ddaf1f`、`c699464bb705742695f91592`、`d9b7b1edd17eeefaa26756c3`、`de5482ebaca9a76160284089`。
- **F9 — 协议层不提供产品模块**：python-a2a 声明 `A2A protocol establishes a standard communication format`、MCP/JSON-RPC 2.0、Agent Discovery；opencode-coord 用 `Typed messages with record ids`。二者是通信契约，不含 Work Item 或 review 语义。Evidence: `5d423995e3d4b2ed0d8aab78`、`8a03946eaf6653ada1427dc9`、`4e9888715cf937cdeac6384a`。

## 3. Semantic coverage review（必须显式记录）

- **路径子串预检**：采集前用脚本把 13 个 criteria 的全部 keyword 与 10 个仓库的 tree 路径做碰撞检查，发现 3 处：`CONTEXT.md` 命中 tasktrooper 的 `*_context.md` 与 mem-vault 的 `templates/CONTEXT.md`（均非 canonical，不产生 hints，已从 keywords 移除）；`agent-self-service-collaboration` 命中 ZAgenticOPN 的 6 个 `docs/**/*.md`（**有意保留**，用于让参照物的 PRD / capability-map 成为 canonical Evidence，且只在该仓库产生 hints）。其余仓库 hints 为空 → fallback 读根 README.md。
- **非路径错配，但存在「同一段落被多个 criterion 引用」**：编译器 excerpt 是命中行前 1 行 + 后 5 行的 6 行窗口，且每个 仓库×criterion 只取第一条。因此 qm 的 `everything it does is audited / security posture` 段同时支撑 `mod-approval-human` 与 `mod-result-provenance`（`c8500b38…`、`fec47fe2…`）；opencode-coord 的首段总览同时支撑 task / result / observability（三条不同 Evidence ID）；mozzie 的 `Git worktree isolation / Review workflow` 段同时支撑 approval 与 result。这些段落确实同时含两组语义，**不是关键词误命中**，但引用时不得把整段窗口当成某一模块的独立证明。
- **弱错配 1 条**：qm `mod-session-context`(`1fcc9288…`) 命中的是 `Each person and each room has its own scoped memory … durable sandbox` 段，主体语义是 scope 与资源，session 语义较弱；同一段也支撑 identity 与 memory。已在矩阵里按「声明存在」而非「已验证 session 设计」使用。
- **覆盖集中**：40/49 Evidence 来自各仓库根 `README.md`，只有 ZAgenticOPN 的 9 条来自 `docs/**/*.md`。技术子系统文档（`docs/SPEC.md`、`memory-records.md`、`capability-tokens.md` 等）结构性未进入 sealed 范围，这是 compiler `isCanonicalPath` 限制，不是项目缺文档。
