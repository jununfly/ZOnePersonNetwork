## Cited findings（仅使用 v2 sealed Evidence）

- **F1 — 产品定位是「并行 coding agent 编排器」，而不是 Work Item 控制面**：README 首屏声明 "The AI Orchestrator for 100x builders"，并行运行 Claude Code、Codex 与任意 coding agent，每个 agent 在各自 worktree；形态是 chat / terminal、本机或云端、把 diffs / browser / CLI 收在一个 app 里。Evidence: `2ed6d70d48ae1d10a19026a0`（`README.md`）。
- **F2 — 编排模型是 coordinator 拆分任务、worker 在独立 workspace 执行并汇总结果**：sealed 摘录写明 "Hand a big task to one agent. It splits the work, starts worker agents in their own workspaces, and brings their results back to you."，并指向 orchestration 文档。Evidence: `75e13f823450ea22d6c7f09f`（`README.md`）。
- **F3 — Agent 兼容面是「终端级」而非控制面契约**："Works with **any CLI agent** — if it runs in a terminal, it runs in Orca."，摘录中列出 Claude Code 与 Codex 的入口。Evidence: `d716c3704d37f7d2b36d2a19`（`README.md`）。
- **F4 — CLI 是 agent 可自行调用的动作面**："Anything you can do in Orca, your agents can do too: create worktrees, start workers, drive the browser and desktop apps, and schedule automations, all from the command line."。Evidence: `3dc1ea964ea53bfbc291171d`（`README.md`）。
- **F5 — Review 是逐行 diff 注解回传 agent**："Review diffs, leave notes on exact changed lines, and send focused feedback back to an agent."。Evidence: `a16d037b586eabaa4c616d4a`（`README.md`）。
- **F6 — 运行时所有权延伸到远端与常驻执行**："Pair a Remote Orca Server, work on any SSH host, or give a worktree its own cloud VM. Your agents keep running when your laptop sleeps."。Evidence: `0a6cfe851c86d1535e2d2fdc`（`README.md`）。
- **F7 — 交付面是三平台桌面构建 + 包管理器**：下载页、macOS arm64/x64、Windows exe、Linux AppImage 与 Homebrew cask。Evidence: `65802a5a91d96fbb669449e8`（`README.md`）。
- **F8 — 特性清单不是稳定契约**："we ship daily, so this list is perpetually behind. The changelog is the real feature list."。Evidence: `17641629769edf434adb6a32`（`README.md`）。注意本条摘录**没有**包含 MIT License 文本，许可证条款不能由这条 Evidence 证明。
- **F9 — 隐私姿态只以文档链接形式声明**："See the privacy & telemetry docs for what anonymous usage data Orca collects and how to opt out."。Evidence: `be542a3a9b72fd240e344418`（`README.md`）。
- **F10 — 仓库 manifest 暴露了工程质量门**：`package.json` 摘录含 `vitest`、`oxlint`、`audit:code-quality`、`test:perf:contracts` 等脚本，说明测试与静态审计由仓库级脚本驱动。Evidence: `bde86e5bbc69853b1656c85c`（`package.json`）。

## Semantic coverage review

- `unknownCriteria = []` **不等于证据充分**：10 条 substantive Evidence 全部来自 `README.md`（9 条）与 `package.json`（1 条）。README 是产品营销文本，package.json 是脚本清单；两者能证明「产品声明了什么」，不能证明「实现如何」「安全边界如何」「升级与凭证谁负责」。
- v1 的反例要保留：把 `README.md` 当作 criterion keyword 会命中仓库里所有 `.../README.md` 路径，导致 `.github/actions/cloud-sql-rollout-lease/README.md` 的 gcloud ADC / Cloud SQL lease 段落被错配成 security、engineering、review 的证据。v2 改用只在正文出现的短语，使导航回落到根 `README.md` + `package.json`，每条 criterion 拿到不同功能段。
- 因此本报告的能力结论只覆盖产品声明层；`SECURITY.md`、`CONTRIBUTING.md`、`AGENTS.md`、`LICENSE` 与仓库元数据作为**非 sealed primary-source reading** 记录在下节，只用于风险、所有权成本与验证门，不进入 Report IR 的 critical claims。
- 热度与契合度分离：118,626 stars、7,533 forks、20 topics 是仓库元数据；`topicMatch = 0` 是 sealed 原值。二者都不作为能力覆盖、语义契合或所有权成本的分数。
