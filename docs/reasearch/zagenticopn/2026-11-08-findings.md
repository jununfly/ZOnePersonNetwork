## Cited findings（仅使用 v2 sealed Evidence）

- **F1 — 产品处于 Experience Version，授权范围被明确收窄**：远端 `README.md` 声明 C 路线实现只对 "same-device, single-project vertical slice" 授权，deployment、production operations 与 deferred collaboration capabilities 均 out of scope。Evidence: `24c521a1983ee68dafa9544d`（`README.md`）。
- **F2 — 生命周期边界是文档级硬约束，不是隐含承诺**：同一段 sealed 摘录把 Product Spec / Experience Version Spec / Candidate-neutral design 列为规范入口，说明能力边界由 Spec 与 roadmap 治理，而不是由 README 特性清单推导。Evidence: `0b78ab7e1b5659a7c049d4f6`（`README.md`，criterion `lifecycle-gaps`）。
- **F3 — 激活是严格 JSON-Call，且请求不携带本地数据库路径**：`docs/experience-version-coordination.md` 说明 `python -m zagentic_opn.activation_runner` 需要 `schema_version`、`intent_id`、`activation_id`、`scope`、`agent_profile`、受控 `host_capabilities`；runner 返回 `claimed` / `no_eligible_work` / `claim_conflict` / `unsupported_host` / `invalid_contract` / `invalid_runtime_config` 等结构化回执。Evidence: `4132ea9292deeab3cf164ca5`（criterion `activation`）。
- **F4 — 异常恢复是 Human 显式操作，不允许 Agent 伪造结果或改库**：sealed 文档设有 "Human exception: reopen a stale claim"，规定 Agent scope 错误或 claim 后消失时，不得 fabricate result、不得直接编辑 SQLite；Human 只能显式 reopen `claimed` 或 `blocked` 的 Work Item。Evidence: `53ce90d514f1eb59d753635b`（criterion `coordination`）。
- **F5 — 共享状态是产品自有 SQLite，消费项目不是其存放位置**：sealed 示例显式使用 `DB=.zagenticopn/shared.sqlite3` 与 `SCOPE=zagenticopn/experience-version` 调用 `python -m zagentic_opn --db ... publish --scope ...`，说明 store 与 scope 是产品侧输入参数。Evidence: `b006b887f99616e81bf87d09`（criterion `state-ownership`）。
- **F6 — 唯一公共 seam 是 `CoordinationProtocol` / activation runner JSON-Call**：sealed 文档称首版实现为 "a small Python module with a SQLite shared context"，Agent 通过 in-process `CoordinationProtocol` 或 canonical `python -m zagentic_opn.activation_runner` 调用；SQLite、event projection、scorecard formatting 是实现细节；激活别名由 ZAgenticOPN 自有 Skill / host adapter 解析，runner 只接受版本化 intent `zagenticopn.activation.check_shared_context.v1`。Evidence: `ce263a867539ddd51588ed09`（criterion `validation`）。
- **F7 — 上述 intent 是 sealed 基线里的 v1 版本**：F6 摘录中的 `zagenticopn.activation.check_shared_context.v1` 与本地工作副本的 `zagenticopn.activation.activate.v2` 不同，属于可观察的版本基线差异（见 Baseline drift）。Evidence: `ce263a867539ddd51588ed09`。

- `unknownCriteria` = `integration-seam`、`security`。**这两项是 unknown，不是 absent**：本次 sealed 采集没有为它们选出 canonical evidence，不得据此断言"没有版本匹配"或"没有审批/校验机制"。
- 验证证据在本轮也偏弱：`validation` criterion 命中的是设计文档首段（描述实现形态），不是测试报告或 scorecard。因此"48/48 测试通过""三周期恢复证据"等结论**不进入 Report IR 的 critical claims**，只作为后续必须复核的对象。
- 结论：本报告的能力判断以 sealed 证据为界；集成与安全结论一律标注为待验证，并转化为落地前的硬验证门。
