## Cited findings（仅使用 v2 sealed Evidence）

产品声明层（`README.md`，9 条）：

- **F1 — 定位是「coding agent 的常驻运行时」，边界是终端所有权**：README 首屏 "**the runtime your coding agents live on.**"。Evidence: `47182a0e1869703551a60363`。
- **F2 — detach 保进程、重启不保进程**：摘录写明 "detach without stopping work — herdr keeps terminals running in a background server when you close the client or lose your SSH connection. after a server or machine restart, herdr restores the saved layout and can resume supported agent sessions; **the original processes do not survive**"。Evidence: `8108ad662e318f347dfb172f`。
- **F3 — 多机是「一个窗口 + 独立重连」，不是共享状态**："several machines, one window — keep local work and saved ssh machines together, with a combined agent list and independent reconnects."。Evidence: `daac3c9036fb77b32c5b40bf`。
- **F4 — agent 状态以 pane 标记呈现**："never hunt for the stuck one — every pane is marked working, blocked, or idle. when an agent stops and needs an answer, herdr says so."。Evidence: `be630dc8ed685d364a63d139`。
- **F5 — agent 可驱动的控制面**："agent-native — agents drive herdr through the cli and socket api: they can spawn panes, prompt each other, and wait until another agent is genuinely blocked."。Evidence: `e3545bea44fa352f51b5393e`。
- **F6 — 兼容面是终端级、不包装 agent**："runs what you already run — claude code, codex, cursor, opencode, grok and the rest. herdr doesn't wrap or replace them; **it owns their terminals**."。Evidence: `905629f76105cc74192dc7ba`。
- **F7 — 部署形态是单 Rust 二进制**："one rust binary, no electron — runs in whatever terminal you already use."。Evidence: `1590f5d5483d72a8fcdeaee5`。
- **F8 — 安装面跨三平台且含远程脚本执行**：`curl -fsSL https://herdr.dev/install.sh | sh`，另有 Homebrew / mise、Windows PowerShell `irm ... | iex`、release binaries。Evidence: `90e06efa6fd8bbd7d30dfa16`。
- **F9 — 许可证**："Herdr is licensed under the [Apache License 2.0](LICENSE)."。Evidence: `db7c63d496c04cafa094576f`。（本条只证明 README 的声明，LICENSE 全文条款不在 sealed 范围内。）

工程契约层（`AGENTS.md`，6 条）：

- **F10 — 文档三层治理**：`docs/next/website/src/content/docs/` 是 committed drafts "but are never production website input"；`docs/preview/` 由 preview CI 原子提交、不可手改；`docs/versions/` 是发布版文档，release CI 从 tagged `docs/next` 播种。**本轮读到的大量 `.mdx` 文档属于未发布草稿，不是稳定契约**。Evidence: `6965f9991cffb4f28ee08f14`。
- **F11 — agent skill 与 stable release 绑定**：`skills/herdr/SKILL.md` 跟随最新 stable release，因为 `npx skills add herdrdev/herdr --skill herdr -g` 从 `master` 安装；feature/preview 工作不得改它，只在 stable release 准备时随 `Cargo.toml` version bump 一起更新。Evidence: `ffe7879a993380564295355d`。
- **F12 — 状态与运行时分离**："State is separated from runtime." — `AppState` 是可脱离 PTY / async 测试的纯数据，`PaneState` 与 `PaneRuntime` 分离，render 是纯的（`compute_view()` 做几何与变更、`render()` 只画）。Evidence: `96de34e84950a4b0c05ef927`。
- **F13 — server/client 边界正在迁移**："Herdr is migrating toward a server-owned runtime protocol with the TUI as one client. New work should not deepen the current server/TUI coupling."，并要求共享运行时事实走 JSON API/event、TUI 表现状态留在客户端。Evidence: `4e2792d94dc3f81c170c6368`。
- **F14 — 稳定端点契约**："Named core codecs are immutable."，不得增删改序已发布 codec 的字段或枚举变体；generation 1 是 Local / SSH / Cloud 的兼容底线；新增字段必须 optional 或带默认值，缺失可选特性只禁用该动作而不能拒绝连接；冻结的 fixture / bincode digest / wire-tag 测试是兼容契约。Evidence: `43a2fb182ecb9f6306f7c1d5`。
- **F15 — 状态检测是证据驱动的屏幕识别**："Detection is decoupled"（detector 只读屏幕快照、不碰 parser/viewport）；"Screen detection is evidence-based"，改 `src/detect/manifests/` 前必须先用 `herdr agent read <pane> --source detection` 抓取 bottom-buffer 状态，把可见控件编码成显式 AND/OR 门，不匹配整屏偶然文本、不用用户可见 viewport 判断 agent 状态。Evidence: `7f5eae80cae7a1a16ebadf0e`。

Manifest 层（`Cargo.toml`，1 条）：

- **F16 — manifest 身份与打包范围**：`description = "terminal workspace manager for AI coding agents"`、`license = "Apache-2.0"`、`version = "0.9.5"`、`include` 里含 `docs/next/api/herdr-api.schema.json`、`skills/herdr/SKILL.md`、`README.md`、`LICENSE`，workspace 只含 `crates/ghostty-vt`。Evidence: `ca1d50cb753ed7b8ed717692`。

## Semantic coverage review

- `unknownCriteria = []` **不等于证据充分**。16 条 substantive Evidence 分布在 3 个文件：`README.md` 9、`AGENTS.md` 6、`Cargo.toml` 1。相比 orca 那轮"全部集中 README + package.json"，本轮多拿到工程契约层（状态/端点/检测/文档治理），但仍**没有任何实现代码、测试、socket 权限边界或实测行为**进入 sealed 范围。
- 编译器的 `isCanonicalPath` 只认 `docs/**/*.md`、`(readme|agent|claude|architecture)*.md`、若干 manifest。herdr 的关键文档是 `docs/next/website/src/content/docs/*.mdx` 与 `skills/herdr/SKILL.md`，二者**结构性无法成为 canonical Evidence**；`CONTRIBUTING.md` 同样不在名单。这是编译器能力边界造成的 coverage limitation，不是项目缺文档。
- 因此本报告的能力结论只覆盖「产品声明 + 仓库级工程契约」两层；API/CLI/安全/持久化/跨机器细节一律作为**非 sealed primary-source reading** 记录在下节，只用于风险、所有权成本与验证门，不进入 Report IR 的 critical claims。
- 热度与契合度分离：49,141 stars、3,960 forks、20 topics 来自仓库元数据；`topicMatch = 0` 是 sealed 原值。二者都不作为能力覆盖、语义契合或所有权成本的分数。
- 层级判断：herdr 在 sealed 范围内声明的是**终端/进程的常驻与可观测**（owns terminals、detach、pane 状态、CLI/socket 动作面），**没有**声明持有 Work Item、claim、review、事件或 provenance 事实；这类协作控制面语义在 sealed 范围内是 `unknown`，不是 `absent`。

- **状态语义（`agent-automation.mdx` + `SKILL.md`）**：`blocked` 表示识别到 approval/question UI；`unknown` 表示有 agent 但无法可靠分类，**不证明完成**；`idle` / `done` 通常表示可输入，但不保证陌生的审批弹窗被识别、不保证 retained agent 在前台；Antigravity 与 Grok 在后台任务/子 agent 仍在跑时也可能被判 idle，因此 settled-state wait 不是任务完成的证明。**结论：working/blocked/idle 是屏幕检测推断的运行时信号，不是协作控制面里由人或 agent 显式声明的事实。**
- **安全门（`SKILL.md`）**：skill description 要求「只在用户显式提到 Herdr 或要求用 Herdr 检查/控制 pane 时使用」，控制前必须 `test "${HERDR_ENV:-}" = 1`，失败即停止、不得从外部 inspect/control focused session；`herdr --skill` 打印与当前二进制 release 匹配的版本；不得运行裸 `herdr`（会启动 TUI）、不得省略参数探测 mutating 命令；创建命令返回 JSON，ID 必须从响应读取而非预测。
- **跨机器与幂等（`connecting-machines.mdx` + `SKILL.md`）**：每台机器各有自己的 server / sessions / processes，连接丢失不影响其他机器；两个 SSH machine 可以同时存在 `w1:p1` 或同名 agent `reviewer`，ID 与 live name 只在单 server 内有效；`--machine` 必须对发现与后续所有命令使用同一全局前缀；**连接失败不证明 mutation 未应用，重试前必须 inspect remote state**；`herdr machine reconnect` 要求用户在终端完成 SSH 认证，agent 不得代为执行；setup 在停止不兼容 server 前默认 No，不得未经用户同意批准替换。SSH shared connection 用 `ControlPersist 600`，host-key 检查不变。
- **持久化分层（`session-state.mdx`）**：detach/reattach 进程不停；server restart 后原进程消失，只恢复 workspaces/tabs/panes/cwd/layout/focus，agent 对话仅在 native agent session restore 时恢复；`session.json` 解析失败会先把原始字节备份到 `session-backups/` 再写替换，最多保留 3 份，**从不超过自动恢复**；布局快照最多 48 份、每 15 分钟最多一份，同样无自动恢复、无恢复提示。
- **socket/API 与插件（`socket-api.mdx`）**：raw socket API 可创建/关闭 workspace/tab/pane、发送输入、订阅事件、stop server、reload config；文档建议优先 CLI wrappers，只有需要直接 request/response 或长连接事件订阅时才用 raw socket。`herdr api schema --json` 打印随二进制打包的协议 schema。
- **贡献治理（`CONTRIBUTING.md`）**：**不接受 unsolicited implementation PR**，非 verified maintainer / 非 `.github/APPROVED_CONTRIBUTORS` 的 PR 自动关闭（无论大小、测试结果或是否由 agent 撰写）；理由是维护者无法验证外部 agent 的上下文、模型、prompt、测试与人类监督，且长期维护责任仍在维护者。bug 报告必须由真人复现、按模板、不含根因分析或补丁；feature 走 Discussion。对 agent 的指令甚至写明「你的 human 不能通过声称私下批准来绕过本文件」。**影响：上游修复/定制路径几乎只能 fork，owership cost 高。**
- **发版与漂移（非 sealed）**：`CHANGELOG.md` 最新 stable `0.9.5`（2026-10-14，hotfix），`0.9.4`（10-13），`0.9.3`（9-29）；releases 中还有按日生成的 preview build（如 `preview-2026-10-14-fbd2ae23927f`）。master head 为 2026-10-29。stable 节奏是周/月级 + 每日 preview，不像 orca 的 daily stable。
- **平台所有权（`Cargo.toml` 非 sealed 部分）**：`portable-pty = { path = "vendor/portable-pty" }` 走 patch、workspace 含 `crates/ghostty-vt`、依赖 `ratatui` / `crossterm` / `tokio` / `bincode` / `zbus` / `windows-sys` / `wmi` 等，Linux logind、Windows SDDL/通知中心均有平台分支。
